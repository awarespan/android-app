# AWARESPAN Android Architecture

*Namespace / Application ID: `com.awarespan.guardian`*
*Target Android Version: minSdk 26 (Android 8.0 Oreo), targetSdk 34 (Android 14)*

---

## 1. Architectural Philosophy & Layering

The application employs clean architecture with a multi-paradigm approach:
- **Presentation Layer (Kotlin + Jetpack Compose)**: Modern reactive declarative UI styled according to the AWARESPAN Zero-Radius Design System.
- **Domain Layer (Java)**: Plain Old Java Objects (POJOs) representing domain models, business rules, incident severity classifications, and repository interfaces. Free of Android framework dependencies.
- **Data Layer (Java + Room + Retrofit)**: Repositories providing offline-first caching, network synchronization, and encrypted token management.
- **Real-Time Communication (Java + OkHttp WebSocket)**: Bi-directional WebSocket event stream for instantaneous incident broadcasting and node telemetry.

## 3. Data & Offline-First Strategy

1. **Room Local Cache**:
   - Acts as an offline cache, **not** the source of truth.
   - When the network is offline or unstable, cached incidents and edge node states remain accessible to the operator.
   - Unsaved local changes (e.g. pending incident verification or policy updates) are tagged and synchronized upon reconnection.
2. **Conflict Resolution**:
   - Backend updates supersede local cache entries based on `updatedAt` ISO-8601 timestamps.
   - AI predictions generated by edge nodes are immutable; human operator verifications update verification states without overwriting original AI inference telemetry.

---

## 4. Edge Node Isolation Boundary

Per security policy:
- The Android application **never** communicates directly with edge hardware over local network protocols (e.g. raw SSH, local RTSP, edge MQTT).
- All interactions flow through the Spring Boot API Gateway (`https://api.awarespan.bchbenjamin.in/`).
- Edge nodes report telemetry to the backend, which streams events to the Android client via encrypted WebSocket (`/ws/events`).
